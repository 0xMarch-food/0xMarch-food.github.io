从 Web3 看区块链的用途

Web1.0 主要是浏览发布者提供的页面，
Web2.0 中用户也生产内容，
Web3 则尝试让一部分身份、资产和应用状态可以由用户控制，并在不同应用中验证或使用。

比特币展示了在开放网络中记账与转移价值的方式，以太坊把这种共同维护的状态扩展到可编程合约，后续公链和联盟链再把重点放在性能、治理、跨组织协作等不同问题上。
以太坊主网于 2015 年以 Frontier 启动，2022 年通过 The Merge 更换共识机制，已有的执行层历史得以延续。 以太坊发布记录 · The Merge

比特币如何验证交易并收敛到主链

区块头、块高与 Merkle 根

比特币的 80 字节区块头包含版本（4 字节）、前一区块头哈希（32）、Merkle 根（32）、时间戳（4）、nBits（4）和 Nonce（4）。当前区块哈希由区块头做两次 SHA-256 得到。块高表示它距离创世区块的位置，从 0 开始。分叉时同一高度可以出现两个不同区块，用区块哈希区分它们。
前一区块哈希连接历史，Merkle 根承诺本区块的交易集合及顺序，当前区块哈希标识本区块。
四笔交易可以组成四个叶哈希 H1 到 H4，先两两合并得到 H12、H34，再向上计算根。
证明某笔交易属于区块时，提供路径上的兄弟哈希和可信的根即可核对。
修改一笔交易会沿路径改变 Merkle 根，进而改变区块头哈希并破坏后一区块保存的引用。

钱包的私钥用于签名，公钥用于验证授权。
传统 P2PKH 地址把公钥依次经过 SHA-256、RIPEMD-160，再加网络版本及校验码并作 Base58Check 编码。比特币还有其他地址类型，这一流程对应传统 P2PKH。

UTXO、找零与手续费

UTXO 是尚未被消费的交易输出。一笔交易引用若干旧输出作为输入，按授权条件逐个验证，然后创建新输出。钱包余额可理解为它能够支配的未花费输出之和。

原题中有两个输入 0.9 BTC 和 0.6 BTC，向商家支付 1.2 BTC，手续费 0.01 BTC。两个旧输出都完整消耗，生成商家输出 1.2 BTC 和自己的找零 0.29 BTC。输入总额减输出总额就是手续费，这里没有给矿工单独创建一个普通交易输出。

共识机制和TPS

机制 谁能参与决定区块 主要权衡
PoW 参与计算、提交符合目标的区块 开放参与需要消耗算力，确认存在重组概率
PoS 质押参与的验证者按协议提议、验证或投票 节省竞争性计算，需考虑权益集中与惩罚机制
DPoS 持币者选出少数负责出块的代表 参与共识的节点较少，出块权和治理可能集中
PBFT 授权副本通过预准备、准备、提交等阶段确认顺序 在其故障模型下可获得确定性结果，消息开销随参与者增加

经典 PBFT 需要 n ≥ 3f + 1，所以 16 个副本最多容忍 ⌊(16−1)/3⌋ = 5 个拜占庭故障。Raft 的典型假设是崩溃故障，适用条件不同。

  • TPS。给定的 1.2 MB、每笔 300 字节和 600 秒出块间隔，得 1,200,000 ÷ 300 ÷ 600 ≈ 6.67 TPS。这个结果取决于区块容量、交易大小和间隔，属于简化估算。
  • 减半与单位。初始补贴 50 BTC，每 210,000 个区块减半。第五次减半后的补贴是 50 ÷ 2⁵ = 1.5625 BTC。发行上限约为 2,100 万 BTC，基本单位 1 BTC = 10⁸ satoshi，所以 0.015 BTC = 1,500,000 satoshi。

PoW、分叉与双花

矿工构造候选区块，尝试改变 Nonce 等影响区块头的内容，寻找数值不高于目标的区块哈希。寻找通常需要多次尝试，验证只需要重算并比较目标。全节点还会独立检查签名、输入是否未花费、区块补贴等共识规则。

收到竞争分支时，先把违反规则的分支排除，再在有效分支中比较累计工作量。

普通节点有多少暂时认可某条链，不是选择主链时的计票依据。

比如 A 有 3 个区块、累计工作量 30，B 有 5 个区块、累计工作量 20，在两条链都合规的前提下选 A。

只有 B 有效且累计工作量更大时，节点才会切换到 B，这个过程叫重组。

同一个 UTXO 在一条有效链中只能花费一次。在短暂分叉中，互相冲突的交易可能曾经分别出现在不同分支。一旦重组，只保留当前主链认可的历史。多数算力提高竞争有效分支的能力，可能造成重组、撤销对自己资金的付款或阻碍交易确认。全节点对签名和发行规则的验证仍然有效。
通常把交易所在块计为第一次确认，后续再有五块就是六次确认。确认深度提高了重组成本，实际需要等待多少取决于风险。

常见的网络风险还包括日蚀攻击（目标节点与正常对等网络隔离）、女巫攻击（用大量身份影响系统）和拒绝服务（资源被耗尽）。连接来源多样化、让共识权重与可验证资源或认证挂钩，以及限制资源占用，分别对应这些问题。

从以太坊交易到 EVM 执行

账户、Nonce 和状态变化

如果说比特币用 UTXO 追踪可花费的输出，以太坊则维护由账户组成的世界状态。执行一笔交易，就是按协议从旧状态计算出新状态。普通外部账户（EOA）由密钥授权签名，合约账户在受到调用时执行代码。账户状态包含 nonce、balance、storageRoot 和 codeHash。对普通 EOA，交易 Nonce 从 0 起顺序使用。图中 0 到 4 已用，当前账户 Nonce 为 5，下一笔就用 5。如果上一笔已经使用了 5 并执行，下一笔才是 6。 以太坊状态树与账户 · 以太坊交易

传统交易字段可记为 nonce、gasPrice、gasLimit、to、value、data 和签名字段 v/r/s。普通合约部署时没有接收地址，data 用来放初始化代码。外部账户签名提交的是顶层交易，被调用的合约再调用其他合约时产生的是执行中的内部消息，没有独立的外部签名和交易 Nonce。一笔交易可以触发多次调用。

EVM 的栈、内存和存储

EVM 按操作码执行字节码，程序计数器指明当前位置，Gas 计量执行成本。栈元素是 256 位（32 字节），最大栈深度是 1024 个元素。 栈放操作数和中间结果，Memory 是本次调用的临时数据区，Storage 保存会进入账户状态的持久数据。调用者、转入金额、交易及区块信息构成执行上下文。 以太坊 EVM 文档

EIP-1559 费用计算

Gas Limit 是允许消耗的上限，Gas Used 是计费使用量。类型 2 交易中，设基础费为 B，用户小费上限为 P，总单价上限为 M。有效的费用设置要求 M ≥ B 且 M ≥ P。执行时实际小费为 min(P, M − B)，实际单价再加上 B。

原题给 B = 25 Gwei、P = 5 Gwei、M = 28 Gwei、Gas Used = 40,000。实际小费只能是 min(5, 28 − 25) = 3 Gwei，总手续费为 40,000 × 28 = 1,120,000 Gwei = 0.00112 ETH。其中 0.001 ETH 的基础费被销毁，0.00012 ETH 归区块的费用接收方。注意 1 ETH = 10¹⁸ Wei = 10⁹ Gwei。

下一块基础费看上一块用量与目标的差异。超过目标会上调，低于目标会下调。图中 1,500 万 Gas 是讲解时的示例目标。协议的目标由当时区块 Gas 上限及弹性规则决定。 EIP-1559 原文

智能合约与扩容

智能合约用代码执行客观条件。比如资金托管合约收到调用后，检查收货确认或退款条件，再决定资金走向。传统合同还要表达难以编码的责任、证据和主观判断，程序化执行也仍依赖代码正确性和链外信息来源。合约部署后一般由交易或其他合约触发。升级既要考虑代码变化，也要考虑谁控制升级权限。

比特币和以太坊的对比可以沿四条线记忆：价值转移与可编程应用、UTXO 与账户状态、Bitcoin Script 与 EVM、PoW 与现行 PoS。
Frontier、Homestead、Metropolis、Serenity 是早期路线图的历史术语。
The Merge 指以太坊转向 PoS，The Surge 是扩容方向。Rollup 在 L2 批量执行，把必要数据与状态承诺等提交到 L1，并按方案使用欺诈证明或有效性证明。

从 Trie 到以太坊状态树

普通 Trie 按前缀共用路径。插入 cat 和 car，都走 c → a，分别在 t、r 分开。dog 从首字母开始走另一支。Patricia Trie 把没有分叉、也没有键结束点的连续路径合并，例如把 c → a 压成 ca。分叉位置仍决定下一步走哪条路。

以太坊执行层的 Merkle Patricia Trie（MPT）再加入哈希与编码，使一个根值能承诺整棵树。Branch 有 16 个十六进制子引用槽位和一个终止值槽位，共 17 项。Extension 存放压缩路径和下一节点引用，Leaf 存放剩余路径和最终值。课堂图中的 ROOT 指根入口或根引用，根位置可以由实际节点占据。在真实状态树中，路径取账户地址的 Keccak-256 哈希，叶子的账户值经过 RLP 编码，区块头保存 stateRoot。短子节点可以直接内联，较长节点用哈希引用。 以太坊 MPT 说明

公链、联盟链和跨链设计

先区分节点部署、准入和治理

公有链通常开放参与，联盟链由多个授权组织共同制定规则和维护网络，私有链的控制权主要由一个组织持有。一个机构可以运行许多台服务器，体现分布式部署。治理是否分散，要看谁有权改变规则、批准成员以及决定如何读取数据。

平台 课上强调的设计
Hyperledger Fabric 成员身份 MSP、链码、背书与排序分工，使用通道或私有数据限制可见范围
FISCO BCOS 开源联盟链，围绕权限、国密和面向产业场景的多机构协作设计
蚂蚁链 用于存证、溯源等产业应用，AntChain Bridge 提供异构链通信的实现参考

公链也采用不同的取舍。EOS 的 21 个经典出块代表、TRON 的 27 个超级代表说明 DPoS，借 EOS 案例讨论选票集中和应用生态。BNB Smart Chain 的特征是 EVM 兼容，Solana 用 PoH 辅助排序，Aptos 和 Sui 则展示 Move 生态的并行执行与对象模型差异。分析要看治理、资源成本和可靠性。 Fabric 私有数据 · FISCO BCOS 文档 · AntChain Bridge

不可能三角是去中心化、安全性、可扩展性之间的一组工程取舍。让更多普通参与者能够完整验证，会带来数据与通信成本。提高处理能力时，应问新增性能来自协议优化、分片、L2，还是更高的节点准入门槛。

协议升级中的硬分叉引入旧规则无法接受的变更，软分叉通常收紧规则，旧节点能够接受按新规则产生的有效区块。普通的短时分叉则可能只是两个矿工几乎同时出块。

侧链、中继链、桥和双向锚定各自做什么

概念 定位 用途
侧链 自己维护账本的业务链 通过桥或锚定机制与主链协作，其安全性取决于自身和桥的设计
中继链 提供协调、安全或验证能力的链 Polkadot 中协调平行链并提供共享安全
跨链桥 让不同网络交换消息或传递资产权益的系统 可以用中继、轻客户端或其他验证机制实现
双向锚定 两条链之间的资产映射规则 源链锁定、目标链铸造，反向时销毁映射、释放源资产

以 1 BTC → 1 WBTC 的为例，原生 BTC 仍在比特币网络内的托管位置。以太坊上的 WBTC 是合约发行的资产，能否按约定赎回依赖托管、验证和跨链机制。反向流程要确认映射资产已被销毁或按机制处置，再释放源链资产。图展示的是锁定与映射的概念模型，具体产品可能另有申购、托管和赎回流程。

Polkadot 内部的中继链+平行链构成多链体系。连接以太坊这样的外部独立网络时，可使用 Bridge Hub 和 Snowbridge 等桥接组件。

Cosmos 用 IBC 传递链间数据包并使用轻客户端等机制核验消息，
WeCross 也是跨链协作平台例子。
常见机制还有多方公证、哈希锁定、侧链或中继、门限签名。门限签名的 3-of-5 是至少三方协作授权的示意。

在供应链金融中，物流链可以把已签收事件及其证明交给银行链。银行核验来源、权限、证明和是否重复处理，然后决定是否触发贷款审核。跨过去的是可验证的业务信息。采用多个组织共同认可的公证人有利于接入异构系统，仍要明确密钥管理、审计和故障时的处置。

稳定币、链上应用和产业融合

三类稳定机制

稳定币尝试把价格锚定在某种参考资产，例如 1 美元。看机制时先问三个问题：资产由什么支撑，谁可以赎回，市场压力出现时谁承担损失。

类型 怎样维持锚定 主要风险
法币储备型 以储备资产支持发行与赎回，课上以 USDT、USDC 为例 储备、托管、发行主体和赎回可用性
加密资产抵押型 超额抵押并设置清算规则，课上用经典 DAI 模型讲解 抵押品价格波动、预言机和清算风险
算法型 依靠供应调整或经济激励影响供需，历史例子是 UST 信心与流动性恶化时可能持续脱锚

浏览器、钱包、预言机和交易所

区块链浏览器查询块、交易与地址记录。
钱包管理密钥，为交易签名。预言机把价格、气象等链外信息传给合约，例如在降雨达到阈值时按合约规则触发保险处理。
预言机的来源、更新延迟和故障处理，决定数据能否作为可信触发条件。

RWA 是现实资产权益的链上表示，代币与现实权利之间仍需要托管、权属确认和可执行的法律安排。

交易所的五项生态影响：促进流动性与价格发现，降低参与门槛，作为部分项目的启动和融资渠道，拓宽资产与应用生态，推动金融创新和机构参与。中心化交易所通常负责撮合和托管，DEX 可用订单簿或自动做市合约交换资产。比较时要看托管、市场操纵、流动性、合约和合规风险。

物联网采集、大数据分析、AI辅助决策

智慧农业里，传感器采集温湿度，网关验证设备与签名。链下保存原始数据和做统计分析，链上记录哈希、来源、授权和访问日志。模型预测灌溉需求或病虫害，再由授权人员或业务系统处理。上链可以帮助发现记录被修改，输入的真实度仍取决于设备、人员和核验流程。

区块链与大数据的融合分成四步：参与采集与共享，作为分析平台的数据源，将数据作为可流通的资产，最后成为支持数据生命周期的基础设施。把四步记成「技术 → 数据源 → 资产 → 基础设施」。

区块链帮助 AI 做可信数据共享、贡献计量、闲置算力协作、跨设备协作和训练过程追溯。AI 可以辅助区块链系统检测异常、优化资源、识别隐私风险和支持智能体协作。
七个方向：改善模型，发现新模型，形成更大范围的洞察，靠审计提高结果可信度，交换数据和模型的价值，细化访问与使用授权，以及支持自主助理。落地时要设计数据授权、链下计算、审计和纠错机制。

中国区块链产业与监管

用两条线理解中国区块链产业。一条是技术和产业：2021 年工信部与中央网信办的指导意见强调赋能实体经济、提升公共服务、夯实产业基础、打造现代产业链、促进融通发展。用到制造业，可以对应产品溯源、可核验的监管数据、接口与安全标准、多机构供应链协作，以及与工业互联网、物联网的结合。文件中的时间节点是规划目标。 2021 年区块链产业发展指导意见 · “十四五”数字经济发展规划

另一条是风险监管。2017 年防范代币发行融资风险的公告、2019 年《区块链信息服务管理规定》和 2021 年防范虚拟货币交易炒作的通知，都是课堂回顾政策演进的历史节点。2026 年八部门发布的《关于进一步防范和处置虚拟货币等相关风险的通知》同时废止了 2021 年通知，并明确涉及现实世界资产代币化的监管要求。文章中的稳定币、交易所与 RWA 图解帮助理解机制，现实项目的合规判断要回到正式文件和适用情形。 2017 年公告 · 2019 年规定解读 · 2026 年通知
